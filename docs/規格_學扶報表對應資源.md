## 1. 要解決的問題

學習扶助評量系統的「特定學生測驗報告」出來之後，老師要知道兩件事：

1. **全班**哪些指標最弱，下一段教學該先補什麼、用哪些資源
2. **每位學生**錯了哪些指標，可以分組或個別補救

目前老師得自己把評量重點對到基本學習內容，再到資源網頁一層一層找。這個工具要把這段流程自動化。

## 2. 三份資料與串接方式

```
測驗報告（每題）                  指標資源對照表                    資源試算表 English 工作表
─────────────────                ─────────────────                 ─────────────────
年級（工作表名稱）      ──┐
基本學習內容類別        ──┼──►  細項編號（如 4-句構-4）  ──►  年級＋領域＋單元 → 所有資源列
評量重點（文字）        ──┘      對應單元／指定資源              （名稱、形式、網址）
學習表現代碼（1-II-x）  ──►  只用來判斷是「聽」還是「讀」
每位學生 Ｏ／Ｘ         ──►  統計通過率、列出每位學生錯了哪些題
```

**用評量重點來串，不用學習表現代碼**。原因是 PDF 和試算表裡都沒有學習表現代碼，而且同一個代碼（例如 3-II-3）底下有好幾個句型，粒度太粗。
這個決定已記在 DECISIONS.md。

## 3. 資料來源規則

### 3.1 資源試算表：只讀，不寫

- 讀取 `English` 工作表的**線上現況**（試算表 ID 見 CLAUDE.md）。GAS 版用 `SpreadsheetApp` 直接讀（以擁有者身分執行，不需要 OAuth token）；本機驗證腳本則用 CSV 匯出網址唯讀讀取。
- **工具絕不寫入任何試算表**，不論是 `English`、`更新紀錄`，還是之後新增的工作表。
- **本機的 `新北英語學扶資源.xlsx` 是舊版**：2026-09-20 比對結果，線上有 258 列，本機只有 215 列；線上已經改過資源形式（例如「AI互動」）、單元名稱（例如「繪本」改成「繪本資源」），也新增了影片。**本機 xlsx 不可當資料來源，也不可用任何方式寫回或覆蓋線上試算表。**
- 如果將來要把對照表放進 Google 試算表，只能**新增一個獨立工作表**，不動既有工作表的任何欄位，而且要先經使用者確認。

### 3.2 指標資源對照表與規則檔（放在**同一份資源試算表**的新工作表）

**2026-09-20 定案**：設定檔放進現有資源試算表（ID 見 CLAUDE.md），新增五個工作表。這樣「改試算表即生效、不必重新部署」的既有承諾對新功能同樣成立——補一列對照，重新整理網頁就生效。

| 新工作表 | 內容 |
|---|---|
| `指標對應` | 細項 → 年級／領域／單元 |
| `評量重點別名` | 已人工確認的評量重點原文 → 細項 |
| `比對規則` | 規則與型態 |
| `字詞主題` | 一字一列的主題標籤 |
| `主題別名` | 報表用字 → 主題標籤 |

**動工作表的規矩（不可違反）：**

- 只能**新增**這五個工作表，**不得修改 `English` 與 `更新紀錄` 的任何一格、任何一欄**
- 我不會直接寫入試算表（目前 OAuth token 也全部失效）。我產出 CSV，由你用「檔案 → 匯入 → 插入新工作表」建立，這個匯入方式不會覆蓋既有工作表
- 程式端**只讀不寫**這五個工作表

下面各節仍以 CSV 欄位描述，欄位順序即工作表的欄位順序。本機另存一份同名 CSV 作為版本控制與備份（repo 的 `data/`），但**線上試算表才是執行時的來源**；兩邊不一致時以線上為準，不可用本機檔覆蓋線上。

**(1) `data/指標資源對照.csv`** — 細項對到資源

`細項編號, 來源, 年級, 試算表領域, 項目, 內容, 對應單元(以｜分隔), 指定資源(以｜分隔), 內容涵蓋度, 備註`

- `來源`：`官方`（PDF 原有細項）或 `自訂`（字詞主題、診斷標籤）。輸出時**自訂細項不得稱為「教育部基本學習內容細項」**。
- `內容涵蓋度`：`直接` / `間接`（用替代資源）/ `無`。這是**人工判斷**，會變的頻率低，所以存在 CSV。

**`資源用途` 與 `媒材完整度` 不存進 CSV，改在執行時依當次抓到的資源推導**（v1.2 修正）：

| 欄位 | 推導方式 |
|---|---|
| `資源用途` | 依該單元實際抓到的資源形式：簡報／影片 → `教學`；遊戲測驗／AI互動 → `練習`；迷思概念（無連結）→ `提示` |
| `媒材完整度` | 教學＋練習都有 → `足夠`；只有其一 → `僅教學`／`僅練習`；只剩提示 → `僅提示`；什麼都沒有 → `無` |

原因：編輯團隊隨時會在 Sheets 新增或刪除資源，靜態存進 CSV 就會再次出現「Sheets 已更新、CSV 還說只有影片」的不同步問題——這正是本機 xlsx 過期的翻版。推導結果要寫進輸出的資料版本區塊（6.3），這樣才知道當次是依什麼資料算出來的。

**(2) `data/評量重點別名.csv`** — 第一級比對用，見第 5 節

`別名ID, 狀態, 年級, 報表類別, 原文(raw_text), 正規化鍵(canonical_key), 對應細項(以｜分隔), 首見報表, 建立日期, 確認者, 確認日期, 依據, 取代別名ID, 備註`

**保留兩種文字**（v1.2 新增）：
- `原文(raw_text)`：報表原始文字，**永不修改**，供人工追查
- `正規化鍵(canonical_key)`：依 5.1 產生，只用於比對

**狀態機**：`待確認 → 已確認 → 已停用／已取代`

- 工具**只使用「已確認」的紀錄**。人工確認的結果先寫成 `待確認`，由確認者填 `確認者／確認日期／依據` 後才改成 `已確認`——避免第一次判斷錯誤就被永久標成「已驗證」
- 判斷錯了不要刪除，改成 `已停用` 或 `已取代`（填 `取代別名ID`），保留稽核軌跡
- **同一組（年級＋報表類別＋canonical_key）不得有兩筆啟用中且結果不同的紀錄**，否則建置階段直接報錯

**(3) `data/評量重點比對規則.csv`** — 第二級比對用

`規則ID, 啟用, 規則型態, 適用年級, 報表類別, 比對方式(精確/子字串/正規表示式), 比對內容, 輸出細項(以｜分隔), 備註`

**規則型態**（v1.2 新增，用來解決「唯一命中」與「一題對應多細項」的矛盾）：

| 型態 | 意思 | 命中多條時 |
|---|---|---|
| `互斥` | 同一報表類別內只能有一個答案（語音細項、字詞主題） | **衝突，送人工確認** |
| `可疊加` | 各自偵測一個特徵，結果取聯集（句構的關鍵片語） | **正常，合併輸出** |
| `修飾` | 依附在其他結果上的附加標籤（`N-診斷-否定`） | 正常，附加上去 |

所以第 22 題命中三條規則（句構 2、句構 3、否定）是**合法的**，因為它們分屬可疊加與修飾型；但語音同時命中兩條互斥規則就是衝突。

- **已移除 `優先序`**：多重命中一律送人工確認，優先序若能壓過其他規則就違反這個原則，留著只會讓人以為衝突可以自動解決。
- **已移除 `預期命中題數範圍`**：題數每期都會變，它是特定測資的性質，不是規則的永久屬性；改放在測試案例檔。
- 測試案例另建 **`tests/規則案例.csv`**：`案例ID, 規則ID, 輸入文字, 應命中(是/否), 預期細項(以｜分隔), 說明`。一列一案例，一條規則可以有多個。**沒有任何測試案例的規則不准啟用。**

**(4) `data/字詞主題.csv`** — 一字一列，主題可複選

`年級, 單字, 主題標籤(以｜分隔), 對應單元(以｜分隔), 備註`

- 一字一列而不是塞在逗號字串裡，`fish` 才能同時標 `動物｜食物`，`want`、`see` 也不必硬塞進「飲食喜好」。
- **主題標籤是語意分類（用來對報表文字），對應單元是資源位置**，兩者分開，不可混用。

**(5) `data/主題別名.csv`** — 報表用字 → 主題標籤（v1.2 新增）

`主題別名, 對應主題標籤, 年級, 建立日期`

報表可能寫「跟動物**有關**」而不是「跟動物**相關**」，也可能寫「動物類」。這是**報表用字**的問題，在 `字詞主題.csv` 加標籤修不好它（那裡管的是單字的語意分類）。兩種資料分開放：句型用字放這裡，單字語意放字詞主題檔。抽出的主題在這裡查不到，就送人工確認。

### 3.3 測驗報告

- 來源：學習扶助評量系統匯出的 xlsx，檔名類似 `YYYYMM特定學生測驗報告 (英語).xlsx`。
- 工具只讀取報表，不修改原檔。

## 4. 報表格式（以 202605 版為準）

| 工作表 | 用途 | 結構 |
|---|---|---|
| `測驗報告統計表` | 依類別彙總 | 第 2 列是標題：序號、基本學習內容、學習表現/學習內容、檢測狀況統計（Ｏ／△／Ｘ／合計），H 欄起每欄是一位學生，值為 Ｏ／△／Ｘ |
| `N年級`（例如 `4年級`） | 逐題明細（**主要讀這張**） | 第 2 列是標題：題號、基本學習內容、學習表現/學習內容、評量重點、檢測狀況統計（E=Ｏ、F=Ｘ、G=合計），H 欄起每欄是一位學生，值為 Ｏ／Ｘ（全形） |

- 第 1 列是報表標題，第 3 列是統計子標題，第 4 列開始才是資料。**解析時不要寫死列號**，要用「第一欄是數字」來判斷資料列（呼應 PITFALLS 裡「不要假設第幾列是標題」這條）。
- 學生欄的標題格式是 `*****12345王小明 (4年級)`（此處為虛構示例），**實際報表含學生真名**，處理方式見第 7 節。
- 一份報表可能有好幾個年級的工作表。工作表名稱符合 `\d年級` 的都要處理。
- 學習表現可能一格寫兩個代碼（`◎1-II-7 …<br>◎3-II-2 …`）。先去掉 `<br>` 和 `◎` 再解析成集合。

### 4.1 讀檔前的格式檢核（任一項不過就停下來報錯，不要硬跑）

1. 標題列必須找得到「題號」「基本學習內容」「學習表現/學習內容」「評量重點」這四個欄名（找不到就是報表改版，停）
2. 題號**唯一**（重複 → 停止）。**不連續只警告**，不停止：未來報表可能因不計分題、刪題或分題編號而跳號，資料仍可安全分析（v1.2 放寬）
3. 每列 `Ｏ數 + Ｘ數 = 合計`
4. `合計` = 學生欄數
5. 每個學生格只能是 `Ｏ`／`Ｘ`（統計表另外允許 `△`）；出現其他值或空白要列出來
6. 學生欄標題不可重複、不可空白
7. 合併儲存格：讀取時取左上角值；若標題列有合併導致欄位錯位，停下來報錯

## 5. 評量重點 → 細項編號的比對規則

### 5.0 三級比對，模糊比對只能提候選

| 級別 | 做法 | 結果 |
|---|---|---|
| 第一級 | 拿正規化後的**評量重點全文**去 `評量重點別名.csv` 做**精確比對**（只看狀態為「已確認」的紀錄） | 命中 → 採用，標「已驗證」，同時執行 shadow check |
| 第二級 | 依 5.2 的規則比對 | **唯一命中** → 採用，標「規則推得」；**多重命中或零命中** → 送第三級 |
| 第三級 | 列入「⚠️ 待人工確認」清單，**不產生教學建議** | 人工確認後寫進別名表，下次就是第一級 |

**多重命中和零命中一樣，都要送人工確認**，不可以自己挑一個——但「多重命中」的定義要看規則型態（見 3.2(3)）：可疊加與修飾型規則同時命中是正常的，互斥型規則同時命中才算衝突。

別名表是隨報表累積的，跑過一期就多一批已確認條目；評量系統改用字時，新寫法會落到第二或第三級，不會被舊別名誤接。

**shadow check（v1.2 新增）**：第一級命中後，**仍然把規則跑一遍**，只是不採用結果。兩邊結果不同時，**採用別名**（人工判斷優先），但要列進資料健康警告。
沒有這一步，別名一旦寫定，之後規則怎麼改都不會再被檢查到，兩套邏輯會靜靜地分岔。

### 5.1 文字正規化與碰撞檢查

**永遠保留兩種文字**：`raw_text`（報表原文，不修改，輸出與追查都用它）與 `canonical_key`（正規化後，只用於比對）。輸出給老師看的一律是 `raw_text`。

**碰撞檢查（v1.2 新增，建置階段必跑）**：把所有別名與規則的 `canonical_key` 建成索引，**同一個 key 對到兩個不同 `raw_text` 時，兩筆都不得進入自動比對**，一律送人工確認並列入健康檢查報告。
因為第 5 步會刪掉所有空白，英文可能因此相撞（例如 `a part` 與 `apart`、`in side` 與 `inside`）。中文評量重點目前沒看到這種案例，但機制要先擋住。

**正規化步驟**（比對前一律執行）：

1. Unicode NFKC 正規化（全形轉半形）
2. **刪除零寬與方向控制字元**：U+200B、U+200E、U+200F、U+FEFF（線上試算表已有實例：資源名稱 `Gemini - CVC Practice2` 前面帶 U+200E）
3. 彎引號 `’ ‘ “ ”` 轉成直引號，破折號統一
4. 去掉 `<br>`、`◎`、`★` 等標記
5. **刪除所有空白字元**（不是合併成一個）。報表寫「能辨識a, e, i, o, u所代表的短母音」，PDF 寫「能辨識 a, e, i, o, u 所代表的短母音」，**只有整個刪掉空白才會相等**
6. 英文轉小寫；中文標點統一成半形

### 5.2 各類別的規則

**互斥型規則必須唯一命中**；可疊加與修飾型規則可以同時命中並合併輸出。判斷衝突時只看同一報表類別內的互斥型規則。

| 報表類別 | 規則 | 範例 |
|---|---|---|
| 語音(字母拼讀規則)（`互斥`） | 取「練習：」之後的文字，依 5.1 正規化（**含刪除所有空白**）後，與該年級語音細項的 PDF 原文比對。**先試完全相等，不相等才試子字串，且子字串只能命中一條**；命中兩條以上送人工確認 | 「能辨識a, e, i, o, u所代表的短母音」→ 4-語音-3-1 |
| 字詞（`互斥`） | 用 `跟(.+?)(相關\|有關)` 取出主題 → 先查 `主題別名.csv`，再查 `字詞主題.csv` 的主題標籤 → 對到該主題的細項。**取出的主題兩邊都查不到，送人工確認**（不可退回「全部」）。只有評量重點原文確實沒有主題字樣（例如「四年級名詞的聽辨」）才對到 `N-字詞-全部` | 「尤其是跟文具相關的單字」→ 4-字詞-文具 |
| 文法句構/字詞（`可疊加`＋`修飾`） | 每個句構的**關鍵片語**各是一條可疊加規則（例如 `is it/this/that`、`what's your name`、`what color`），命中幾條就輸出幾個細項，**這不算衝突**；「否定」是修飾型規則，附加 `N-診斷-否定` | 「It's an apple.及It's red.(含否定…)」→ 4-句構-2、4-句構-3、4-診斷-否定 |
| 常用語（`可疊加`） | 報表只寫「常用語的聽辨」時，對到該年級的「聽說」和「聽懂」兩項；如果寫出了具體用語，就依用語清單比對 | → 4-常用語-聽說、4-常用語-聽懂 |
| 字母（`互斥`） | 對到 `3-字母-1`；如果寫出了具體字母，可以縮小到對應的 Unit（第二階段再做） | |
| 篇章/文本（`互斥`） | 對到 `N-篇章-1` | |

**比對不到、或互斥型規則命中多條的題目絕不能默默略過**。建議單最後要有「⚠️ 待人工確認題目」一節，列出題號、**原文**評量重點（raw_text）、命中了哪幾條規則與其型態，請維護者確認後寫進別名表（狀態先是 `待確認`）。
這種情況通常發生在新年級第一次出報表，或評量系統改了用字。

**聽／讀判斷**：把學習表現欄解析成**集合**，不是只看第一個。`1-` 開頭加入「聽」，`3-` 開頭加入「讀」，一格同時有 `◎1-II-7` 和 `◎3-II-2` 時就是 `{聽, 讀}`，兩者都要顯示。
第一階段只在建議單上顯示「這題考的是聽／讀」，資源本身不分聽讀，因為四年級資源在試算表裡沒有標示。第二階段是否補標，見第 10 節。

## 6. 輸出內容

### 6.1 全班建議（給授課老師）

依「細項」彙總：同一細項的多題合併計算通過率，**由低到高排序**。

**不做紅黃綠分級**（2026-09-20 定案）。全班 14 人時一位學生就是 7.1 個百分點，答對 6 人和 7 人會落在不同級、10 人和 11 人也會；再加上每個細項只有 1～6 題，任何固定門檻都會給出一個它撐不起的判斷。改成只排序、只呈現數字，由老師判斷要處理到哪裡。

所以建議單上：

- 依通過率由低到高排，**不標「已掌握」「待加強」這類結論**
- 一律顯示**原始數字**（題數、學生數、各題答對人數），百分比只是輔助
- 題數只有 1 的細項標「ⓘ 只有 1 題，證據不足」
- 同一細項各題通過率**最高與最低相差 ≥ 30 個百分點**時，標「⚠️ 題目難度不一致，請看原題」。例如第 20、24 題評量重點一字不差，卻是 9/14 和 2/14；`4-句構-2` 六題從 14/14 到 2/14，合併成 58% 會把這個差異蓋掉
- **複合題**（一題對應多個細項，例如第 22 題同時計入句構 2、句構 3、否定）要標「綜合題，無法判斷錯在哪個成分」，且該細項的統計要另外註明含幾題複合題。複合題和單一考點題不可用同樣的信心呈現
- 預設**展開通過率最低的前幾項**的資源，其餘收合但可展開——這是版面考量，不是能力判定

每個細項展開後顯示以下內容：
- 細項編號（自訂細項要標「自訂」）、PDF 內容原文、相關題號與各題答對人數、這題考聽或讀
- **迷思概念**（試算表中「類型＝迷思概念」的提示）排在最前面，並標明**這是文字提示、沒有連結**
- 資源清單：名稱、形式圖示、連結，依形式分組（簡報／遊戲測驗／影片／電子書／AI互動／文件）
- **可點資源數與提示數分開顯示**（例：「可用資源 5 筆、提示 2 則」）。線上 258 筆中有 21 筆是無連結的迷思概念提示，不可以拿提示充當教學資源
- `內容涵蓋度=間接`、`媒材完整度=僅教學／僅提示／無` 要顯示提醒，例如「本細項只有影片、沒有練習，建議搭配三年級音韻覺識 Unit 3、4」

一題如果對應到多個細項，就計入每一個細項。例如第 22 題同時計入 4-句構-2、4-句構-3、4-診斷-否定（後者是自訂標籤）。

### 6.2 學生個別建議（給授課老師，不發給學生或家長）

- 依學生列出答錯的題號 → **細項**，每個細項以頁內連結指到全班區該細項的**完整資源清單**
- **不在個別學生區挑選前幾筆資源**（v1.2 回退 v1.1 的做法）。只顯示三筆而把其餘藏起來，實際效果就是幫老師做了選擇，加一句「請自行取捨」並不能抵消這個偏誤——因為老師根本看不到被藏起來的資源。工具沒有能力判斷哪幾筆最合適：試算表沒有「這筆資源對應哪些字／句型、適用聽或讀、是教學還是練習」的欄位
- 若之後真的需要在學生區直接顯示資源，必須預設**全部展開**或提供「展開全部」，且**不得使用「最直接」「最推薦」這類字眼**
- 要做到有根據的挑選，得先在試算表補欄位（見第 10 節待決 4）
- 另外提供「**錯誤相同的學生分組**」：把答錯同一細項的學生列在一起，方便分組補救

### 6.3 附帶

- **資料版本區塊**（放在建議單開頭）：試算表抓取時間、抓到幾列、內容雜湊（SHA-256 前 8 碼）、報表檔名、對照表與規則檔的版本。線上試算表隨時在變，沒有這段就無法回答「當時老師看到的是哪一版」
- ⚠️ 待人工確認題目清單（見第 5 節）
- 對照表中找不到的單元：如果試算表改了單元名稱，對照表指到的「年級＋領域＋單元」就會找不到資源。工具要列出這些失效的鍵，**不可以靜默輸出空清單**。「繪本」改成「繪本資源」就是一個真實案例。
- 共通資源：歷屆考古題、重點整理

## 7. 學生個資與產出安全

### 7.1 個資（GAS 網頁版，2026-09-20 定案）

- **姓名不離開老師的電腦**：報表在瀏覽器端解析，姓名就地換成代號，送到 GAS 的只有代號與作答結果（流程見 8.1）
- **伺服器不儲存**：GAS 端不寫 Sheets、不寫 Drive、不寫 Properties，算完就回傳
- 代號↔姓名對照只存在該分頁記憶體，**不寫 localStorage**；關掉分頁就沒了
- 老師若把結果列印或另存 PDF，那份檔案含姓名，屬於老師自己保管的個資，請存在學校電腦、不要放雲端硬碟共用資料夾
- 報表原檔 xlsx **不要放進本專案資料夾**；若為了測試放了，`.gitignore` 已排除（`*特定學生測驗報告*.xlsx` 與 `輸出/`），但更安全的是根本不放
- 保存與刪除：網頁版不留檔，所以沒有清理需求。本機測試用的檔案，測完自己刪

### 7.2 網頁安全要求

資源名稱與評量重點都來自可被編輯的外部資料（試算表、報表），所以：

- **所有插入 HTML 的文字一律 escape**（代號、資源名稱、評量重點），包含 `< > & " '`
- 資源網址只允許 `https:` 和 `http:`，其餘（`javascript:`、`data:`、`file:`）一律不輸出連結，改顯示純文字並標記
- 不使用 `innerHTML` 拼接；以 `textContent` 或模板搭配 escape 函式產生
- **不從 CDN 動態載入未鎖版本的函式庫**；需要的前端函式庫內嵌進專案（見 8.4）
- 既有的 GAS 慣例照舊：不可用 template literal，網址中的 `//` 要拆開

## 8. 產出形式：GAS 網頁版，姓名在瀏覽器端就換成代號（2026-09-20 定案）

老師在現有的資源網頁上傳報表，直接看到建議單，不必安裝任何東西。

### 8.1 姓名絕不離開老師的電腦

```
老師的瀏覽器                                  GAS 伺服器
──────────                                  ──────────
1. 選取報表 xlsx（不上傳原檔）
2. 在瀏覽器裡解析，抽出：
   題號／基本學習內容／學習表現／評量重點
   每位學生的 Ｏ／Ｘ
3. 姓名 → 代號（學生1、學生2…）
   代號↔姓名對照表只存在這個分頁的記憶體    ──►  4. 只收到代號與作答矩陣
                                                 5. 比對細項、抓資源、算統計
6. 收到結果後，在瀏覽器把代號換回姓名     ◄──  （伺服器完全不知道姓名）
7. 老師列印或另存 PDF
```

- **上傳的內容不含姓名**，GAS 執行記錄裡也不會有。
- 代號↔姓名對照**不寫入 localStorage、不寫入任何試算表**，關掉分頁就沒了。老師重跑一次就好。
- 伺服器端**不儲存任何一次查詢的結果**（不寫 Sheets、不寫 Drive、不寫 Properties）。要做跨學期比較得另外討論，目前不做。

### 8.2 設定檔放哪裡

**2026-09-20 定案：放進現有資源試算表的五個新工作表**（`指標對應`、`評量重點別名`、`比對規則`、`字詞主題`、`主題別名`），GAS 用同一個 `SpreadsheetApp.openById` 一起讀。

- 改對照表**不必重新部署**，與現有「改試算表即生效」的行為一致
- 只新增工作表，**不動 `English` 與 `更新紀錄` 任何一格**
- repo 的 `data/` 保留同內容 CSV 作為備份與版本控制，但**執行時以線上為準**；不可用本機檔覆蓋線上
- 配套的驗證與容錯見 9.1

### 8.3 GAS 實作限制（專案既有慣例，寫的時候就要遵守）

- **不可用 template literal**（反引號字串），一律字串串接
- 網址中的 `//` 拆成 `'https:/' + '/...'`
- **不可用 hash 路由**，新頁面用查詢參數（例如 `?page=report`）
- 部署一律 `clasp push && clasp deploy --deploymentId <現有 ID>`，**絕不新建部署**
- HTML 超過約 27K 字元要把 `<script>` 分離成獨立 `.html`
- `doGet()` 不可呼叫會觸發 OAuth 的函式
- 資源資料改用 `SpreadsheetApp` 直接讀（GAS 以擁有者身分執行，不需要 OAuth token，也不再需要 CSV 匯出那條路）

### 8.4 瀏覽器端解析 xlsx

需要在前端讀 xlsx，預計用 SheetJS。這與 7.2「不引用外部資源」有衝突，處理方式：

- 優先**把函式庫內嵌**進 GAS 專案檔（鎖定版本，不吃 CDN）
- 若檔案過大無法內嵌，改請老師先把報表另存成 CSV 再上傳，前端只解析 CSV，不引入任何外部函式庫
- **不接受**從 CDN 動態載入未鎖版本的函式庫

## 9. 維護流程

1. 新一期報表出來 → 執行工具 → 看「待人工確認題目」與「資料健康檢查」兩節
2. 待確認的題目 → 確認後寫進 `評量重點別名.csv`（精確比對），必要時再補一條規則並附測試例 → 重跑
3. 編輯團隊在試算表新增資源 → 不用做任何事，只要單元名稱沒改，就會自動帶出
4. 每次執行都要輸出的**資料健康檢查**：
   - 失效的單元鍵（對照表指到的「年級＋領域＋單元」在試算表找不到）— 「繪本」改成「繪本資源」就是真實案例
   - 失效的**指定資源名稱**（比對前先套 5.1 正規化，特別是零寬字元）
   - 同一單元內的**重複資源名稱**（重複會讓指定資源指向不明）
   - 只有提示、沒有任何可點資源的細項
   - 空網址、非 http(s) 網址
   - 互斥型規則命中多條的題目
   - **canonical_key 碰撞**（同一個正規化鍵對到不同原文）
   - **shadow check 不一致**（別名結果與規則結果不同）
   - 別名表中狀態為 `待確認` 的紀錄（提醒補簽核）、以及被 `已停用／已取代` 的紀錄數
   - **反向檢查：試算表有、但對照表還沒收錄的單元**（v1.4 新增）。編輯團隊新增一個全新的單元名稱時，資源抓得到，但系統不知道它屬於哪個指標，就不會出現在任何建議裡。每次執行都要列出來，例如「⚠️ 有 2 個單元尚未對應到指標：四年級／字詞與文法句構／Unit 9…（這些資源不會出現在建議中）」。看到提醒就到 `指標對應` 工作表補一列，重新整理即生效
5. **連結是否還活著**不自動檢查（需要對外連線）。提供 `--check-links` 選項，由維護者定期手動跑一次
6. 報表換了主題用字（例如改寫「跟動物有關」）→ 落到人工確認 → 在 **`主題別名.csv`** 補一列對應；`字詞主題.csv` 管的是單字語意，不要拿來修用字問題，也不要改細項編號

### 9.1 設定檢查與容錯（v1.4 改寫）

設定檔放線上可以即時生效，代價是**也能即時改壞**。所以：

1. **網頁上的「檢查設定」按鈕**：改完對照表按一下，立刻知道哪一列寫錯（取代原本規劃的 `--validate-config` 指令，老師不必跑指令）
2. **每次執行前自動驗證一次**
3. **驗證失敗不讓功能壞掉**：顯示「`指標對應` 第 12 列有問題：細項編號不存在」，同時**沿用上一次驗證成功的設定**（用 `CacheService` 保留）繼續運作，而不是整頁掛掉
4. 驗證成功時才更新快取，並記錄當次的設定版本（寫進建議單的資料版本區塊）

檢查項目（用白話回報第幾列、哪一欄、應該填什麼，不可以直接丟出程式例外）：

- 欄位數、欄名、分隔符號（`｜` 與 `,` 用錯）
- 細項編號是否存在於對照表；有沒有重複鍵
- 正規表示式能不能編譯
- 列舉值是否合法（狀態、規則型態、內容涵蓋度）
- 每條啟用中的規則是否至少有一個測試案例
- canonical_key 碰撞、別名衝突（同鍵不同結果）
- 對照表指到的單元在 `English` 工作表找不到（正向）、`English` 有而對照表沒收錄的單元（反向）

## 11. 驗收標準

「25 題全部有對應」本身**不是**安全的驗收條件——規則寫得越寬鬆越容易達標。所以驗收要比對**預期的精確細項集合**，而且要驗「不該命中的不會命中」。

### 11.1 golden set（人工獨立建立並簽核，存 `tests/golden_202605_4年級.csv`）

- 25 題逐題的**預期細項集合**（例：第 22 題 = `{4-句構-2, 4-句構-3, 4-診斷-否定}`）
- **必須直接依報表原文與基本學習內容 PDF 由人工判斷建立，不可由對照 CSV 或規則自動產生**（v1.2 修正）。對照表的驗證表、規則、golden set 若都源自同一份判斷，驗收就是自己驗自己：原表判錯，實作和 golden set 會一起錯，而且驗收全綠
- 欄位含 `簽核者, 簽核日期`。對照表裡由 AI 整理的驗證表只能當**草稿**，要由老師逐題看過報表原文後簽核
- 工具輸出必須與 golden set **完全相等**：多對到或少對到都算失敗

### 11.2 比對正確性

- [ ] 25 題逐題的細項集合與 golden set 完全相符
- [ ] 「待人工確認」為空
- [ ] **反例測試**全部落到人工確認、不被誤接：
  - 主題改寫（「跟交通工具相關的單字」這種 4 年級沒有的主題）
  - 空白位置改變、彎引號改直引號、夾帶 `<br>` 或零寬字元
  - 未知句型（例如 6 年級句型出現在 4 年級報表）
  - 一段文字同時符合兩條規則

### 11.3 統計正確性

v1.1 原本要求「用第二支腳本重算 350 格」。第二輪指出：若第二支腳本用同一套 Excel 函式庫與同樣的欄位判斷邏輯，共同錯誤照樣抓不到，卻要多養一套解析器。改成三段（v1.2）：

- [ ] **不變量檢查**：每題「學生格中 Ｏ 的個數」必須等於報表自己的 E 欄統計、Ｘ 的個數等於 F 欄、兩者相加等於 G 欄與學生欄數。這是用報表的官方統計去驗自己的解析，不依賴第二套實作
- [ ] **固定儲存格人工核對**：挑固定的 10 格（記錄工作表、儲存格位址與預期值，存進 `tests/`），每次比對。用位址而不是抽樣，才能重現
- [ ] 每個細項的題數、答對人數、通過率與規格 6.1 的手算表相符
- [ ] 證據不足（題數 = 1）、異質性（差距 ≥ 30 個百分點）、複合題三種標記都有出現在該出現的地方

### 11.4 資料完整性

- [ ] 每個「年級＋領域＋單元」鍵在線上試算表都找得到。**「找得到資源」必須是有網址的資源**；只有無連結迷思提示的細項要被列為「尚無可用教學資源」，不可算通過
- [ ] 每個指定資源名稱都找得到（正規化後比對）
- [ ] 所有輸出的網址非空且是 http(s)

### 11.5 安全與產出

- [ ] 頁面不從 CDN 動態載入未鎖版本的函式庫；前端函式庫已內嵌
- [ ] **用離線測試檔驗證跳脫**（v1.2 修正）：在 `tests/fixtures/` 放含 `<script>`、`javascript:` 網址、`"` `'` `&`、超長字串的假資源 CSV 與假報表 xlsx，全程不連線、不碰任何線上試算表。原本寫「在試算表測試副本放一筆 `<script>`」既需要目前沒有的 OAuth 寫入權限，也讓安全測試依賴外部服務
- [ ] **姓名不外流**：用瀏覽器開發者工具檢查送往 GAS 的請求內容，**不得出現任何學生姓名**，只有代號
- [ ] GAS 端執行後，資源試算表、Drive、Script Properties 都沒有新增任何資料
- [ ] 執行前後，線上試算表的列數與內容**沒有任何改變**（工具只讀）
- [ ] 個資未進版控：`git ls-files` 中**沒有**報表 xlsx 與 `輸出/` 下的檔案，且 `git check-ignore` 對兩者都回報命中。只看 `git status` 不夠——已被追蹤的檔案就算符合 `.gitignore` 仍留在版本庫裡

### 11.6 三層驗收節奏（v1.2 新增）

全部項目每次都跑會拖垮開發，依成本分層：

| 何時 | 跑什麼 |
